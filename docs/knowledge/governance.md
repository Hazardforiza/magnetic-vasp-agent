# VASP RAG 知识治理规范

本规范约束未来 RAG 的资料来源、引用、冲突处理和知识晋升。第 10.1 步只建立来源清单和评测基线，不解析正文、不生成 embedding、不连接模型 API。

## 权威层级

同一问题出现冲突时，按以下顺序处理：

1. 确定性代码中的类型和安全约束；
2. 与目标 VASP 版本匹配的官方资料；
3. 用户确认的组内规则；
4. 人工确认且具有完整输入、版本和结果记录的历史案例；
5. 已确认的运行故障经验；
6. 尚未确认的个人笔记和课程材料。

较高层级不会自动证明某一计算在科学上收敛。若两个来源适用版本或计算目标不同，应同时展示差异，不得用单一“置信度”掩盖冲突。

## 来源类型

- `official`：VASP 官方 Wiki、手册和版本说明。网页只有在保存本地快照、来源 URL、获取日期、适用版本和内容哈希后才能进入正文索引。
- `team_policy`：节点白名单、审批要求、模块环境等本组规则。它约束操作，但不替代 VASP 物理依据。
- `validated_case`：由用户确认成功、输入与输出完整、VASP 版本和赝势标识明确的案例。未经确认的历史文件不能归入此类。
- `runtime_experience`：真实运行中出现的错误、诊断、人工确认原因和最终修复。模型猜测不能直接写入。
- `personal_note`：课程资料、个人笔记、历史输入和派生摘要。默认只用于提出待核实线索。

`source_type` 表示来源身份，`validated` 表示当前内容是否经过人工确认，两者不可混用。

## 内容与许可证边界

- POTCAR 及其变体永不进入知识库、embedding、提示词、日志或 Git。
- `WAVECAR`、`CHGCAR`、`OUTCAR`、`vasprun.xml`、`DOSCAR`、`PROCAR` 等原始运行文件不作为通用 RAG 文档；后续只保存结构化、脱敏且带来源哈希的结果摘要。
- `local_only` 资料只能在本机处理，不复制到仓库或外部 API。使用远程 embedding/LLM 前必须另行审查数据发送范围。
- `reference_only` 网页在第 10.1 步只保存 URL 和声明哈希，不抓取正文，也不声称已验证其内容。

## 切块与引用要求

后续切块以章节、INCAR 标签或完整操作步骤为语义边界，不能把条件和结论拆开。每个知识片段必须保留：

- 来源 ID、标题、路径或 URL；
- 原始文档 SHA256 和片段 SHA256；
- 章节、页码或可复核定位信息；
- 来源类型、VASP 版本、任务和磁性模式；
- 是否已验证、是否需要人工复核；
- 抽取器和切块规则版本。

Agent 的专业结论必须引用实际命中的片段。没有依据时输出 `evidence_missing`，不能用语言流畅程度代替证据。

## 冲突与知识晋升

检索结果冲突时，回答必须列出各自来源、适用条件和未解决点。任何个人笔记或运行经验晋升为 `validated_case` 前，都必须由用户审查：结构与原子顺序、四个输入文件、VASP 版本、POTCAR 标识、收敛证据、目标物理量及结果摘要。

RAG 只提供证据和建议。INCAR、KPOINTS、POTCAR 选择、Workflow、节点和 MPI 参数仍必须进入现有类型化模型并通过确定性校验；知识库不能修改白名单、跳过审批或直接执行 shell。
