# 组内 VASP 集群策略

本文件记录已经确认的**全组**运行边界，供 RAG 引用和人工审查。它不绑定某一个集群账号。真正的强制执行由共享站点模板 `config/execution/site.team.json` 与每人本机合成的 `ClusterProfile` 完成。

- 跳板短主机名是 `mu01`。工位电脑通常连 `192.168.164.203:7722`；外出或笔记本可用本机隧道 `127.0.0.1:17722`。登录后仍必须验证主机为 `mu01`、用户为**当前操作者自己的账号**。
- `mu01` 只允许作为跳板，禁止在其上启动 VASP、MPI 或其他计算任务。计算节点之间的内部 SSH 仍为 22。
- 当前允许使用的计算节点仅为 `cu20`、`cu21`、`cu22`、`cu23`、`cu38`、`cu39`、`cu40`、`cu41`、`cu43`、`cu48`、`cu49`、`cu50`。`cu42` 不在当前白名单内；历史资料中的节点名称不构成授权。
- 集群没有 Slurm；目标运行方式是在获批的单个计算节点上使用 Intel MPI 和 VASP 5.4.4。
- 每人使用自己的远端目录 `/home/<user>/magvasp/runs`。不得把别人的家目录写进 profile，不得查看、修改、信号或取消其他用户的作业。
- 节点负载快照不等于资源分配。`cu21` 曾被其他用户占满物理核心；启动前必须用最新 probe 确认。
- 站点模板可以共享；用户名、连法、是否启用执行、密钥和密码必须留在本机 identity / SSH 里。
- LLM 可以解释预检结果和提出计划，但不能选择白名单之外的节点、生成任意 shell、绕过审批或自动重试。

- 用户提供的 topsst.sh 会并行查看这些节点的 top/sensors；它只能作为占用参考，不能替代 probe 或资源分配。


- scripts/topsst.sh 是节点占用查看参考；Agent 可在固定脚本路径下调用它生成候选，但仍必须经过 probe 和人工资源审核。

- scripts/submit_vasp_reference.sh 是用户提供的 VASP 任务准备/提交参考脚本；它包含 SCF/DOS/Band/Wannier 目录复制和固定命令模板，但不作为 Agent 的可执行入口。
